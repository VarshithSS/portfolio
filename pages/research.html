Ongoing LLM Agents Medical AI Uncertainty Estimation

Reliable and Interpretable Medical AI
Tool Orchestration for Cardiac MRI

Singampalli Sri Varshith  ·  Guide: Prof. Arnab Bhattacharya, Department of CSE, IIT Kanpur  ·  July 2026 — Present
An agent answering a cardiac MRI question does not produce one decision — it produces a chain of them: which tools to invoke, in what order, with what inputs, and how much to trust each result. Final-answer accuracy collapses all of that into a single number, and in doing so hides the failure mode that matters clinically: an agent that reached the right answer through the wrong reasoning, or reached it by luck. This work builds the ground truth and the evaluation machinery to score the trajectory rather than just its endpoint, and layers uncertainty estimation across every level of the workflow so the agent can report how confident it actually is.
Why Final-Answer Accuracy Is Not Enough
What a single accuracy number hides

Two agents can score identically on final-answer accuracy while behaving completely differently underneath. One selects the correct tools and sequences them properly. The other calls six tools where two would do, ignores half the outputs, and lands on the right answer anyway.

In a clinical setting those are not equivalent systems. The second is unreliable in a way the metric cannot see, and will fail unpredictably on the next case.

What the trajectory tells you instead

Annotate the tools a question actually requires, the ones that are merely optional, and the ones that are irrelevant — plus the expected calling sequence and inputs — and the behaviour becomes measurable.

You can then ask precise questions: did it pick the required tools? did it call anything unnecessary? did it order them correctly? did it miss something it needed?

Ground-Truth Tool-Call Trajectories
Annotation schema
Each cardiac MRI question is annotated with a full reference trajectory, not just a reference answer. This is what makes systematic evaluation of agent orchestration possible in the first place.
required
Tools the question cannot be answered correctly without. Missing one is a hard failure.
optional
Tools that add supporting evidence but are not strictly necessary. Calling them is neither rewarded nor penalised.
irrelevant
Tools with no bearing on the question. Calling one is an unnecessary call — noise, latency and a signal of poor reasoning.
sequence
The expected order of calls. Some tools consume the output of others, so order is part of correctness, not a stylistic preference.
inputs
The expected arguments to each call. A tool invoked correctly but parameterised wrongly still produces a wrong result.

F1 The balance between the two
Sequence correctness Right tools, wrong order — broken data dependencies
Unnecessary-call rate Cost, latency and reasoning noise

3

Multi-Level Uncertainty Estimation
A single confidence score attached to the final answer tells a clinician almost nothing about where the agent was unsure. Uncertainty is estimated at four distinct levels instead, so low confidence can be traced to its origin — a wavering tool choice, a noisy tool output, an unreliable workflow shape, or genuine ambiguity in the clinical answer itself.
Level 1 — Tool selection
How confident is the agent that this is the right tool for this question? Low confidence here suggests the question is out of scope for the available toolset.
Level 2 — Individual tool outputs
How reliable is what each tool returned? A correctly chosen tool can still produce a low-quality result on a difficult scan.
Level 3 — Workflow-level call sequences
How confident is the agent in the shape of the whole trajectory? This is where compounding errors across a chain of calls become visible.
Level 4 — Final clinical answer
The end-to-end confidence a clinician actually sees — now decomposable into the three levels underneath it rather than opaque.
